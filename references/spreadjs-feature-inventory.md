# SpreadJS 官方功能清单使用说明（v19.2）

清单文件：`references/SpreadJS 功能清单（v19.2）.xlsx`（190KB，随 skill 分发，无需再向客户索要）。

## 为什么必须用

Excel 基准只能告诉你"Excel 有什么"，功能清单告诉你"**对方宣传自己有什么**"。两者取并集才是完整测试面：
- 只看 Excel 基准 → 漏测对方独有能力（圆角边框、单元格折角、自动合并、文本省略符都是这么漏的）；
- 只看功能清单 → 漏测 Excel 有而对方没宣传的（如中文大写金额、条件段格式）。

清单里带 `V19.2 新增 / V19.2 增强 / Vxx.x` 版本标记的行尤其值钱：既是版本差异素材，也是"对方最近在投研发的地方"，销售对抗时最需要知道。

## 用法

```bash
# 1) 看模块分布
python scripts/extract_feature_inventory.py "references/SpreadJS 功能清单（v19.2）.xlsx"

# 2) 导出某模块全部条目为 md 表格
python scripts/extract_feature_inventory.py "references/SpreadJS 功能清单（v19.2）.xlsx" --module 05 --out items.md

# 3) 按关键词筛选（特性/功能名任一命中）
python scripts/extract_feature_inventory.py "references/SpreadJS 功能清单（v19.2）.xlsx" \
  --module 05 --grep 格式,填充,合并,对齐,字体,样式 --out fmt.md
```

## 反推规则

1. 清单条目是"能力主张"，不是"API 证据"。**仍须回到官方文档找到对应 API 与 URL**，找不到就记"对方宣传但文档无公开 API"，这类项在报告里比"不支持"更有杀伤力。
2. 一条清单条目往往能拆成多个测试项。例："单元格填充效果（渐变/路径渐变/图案）" → B2 图案类型、B3 前景色、B4 背景色、B5 渐变角度、B6 渐变停靠点、B7 渐变类型 6 项。
3. 清单里明确写"增强"的，重点测边界（如 V19.2 填充增强：全角数字 ０-９ 的序列填充）。
4. 清单没写但 Excel 有的，照样进测试项，来源标"Excel 基准"。
